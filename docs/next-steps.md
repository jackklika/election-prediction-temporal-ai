**The candidacy agent returned zero records, the cause is known, and the fix is
in.** It has not been re-run — that is item 1 below.

Root cause, from the Logfire trace: **both live runs ended with
`finish_reason: length`.** `max_tokens` was never set, so pydantic-ai's default of
**4096** applied; the structured output was truncated mid-generation, and because
`CandidacyFindings` defaults its list fields to `()`, a truncation was reported as
a clean run that found nothing. `agents/base.py` now sets
`AGENT_MAX_TOKENS = 32_000` explicitly.

Two things compounded, both documented in this repo before they bit:
adaptive thinking is **on by default** on Sonnet 5 and counts against the same
`max_tokens` budget, and the candidacy agent pins `effort="high"` — so the
ceiling was being spent on thinking before any answer was written. The earlier
run burned 4,096 output tokens, the later one 19,010, and neither finished.

The *storage* model is proven (13 lifecycle tests on fixture data with the real
dates). The *agent* is unproven either way: it never got to emit a complete
answer, so nothing is yet known about whether it can read a timeline out of prose.
`endorsed` has a code writer and tests but no live data.

2. **Make empty output loud** — worth doing regardless of whether it is still
   broken. Both `CandidacyFindings` fields default to `()`, and so do

   no anchor. Consider looking up the *contest* instead.

   and `ScrapedEndorsement` repeats every race field. Since the caller usually

### 1b. Reading Logfire traces — worth the ten minutes

This is how the truncation was found, and nothing else would have shown it. The
CLI's `logfire read-tokens create` is **broken** in the installed version
(`AttributeError: 'Namespace' object has no attribute 'organization'`), so mint a
token through the client directly:

```python
from logfire._internal.client import LogfireClient
LogfireClient.from_url(None).create_read_token("jackklika", "electalpha")["token"]
```

Then query spans as SQL:

```bash
curl -s -G https://logfire-us.pydantic.dev/v1/query \
  -H "Authorization: Bearer $LOGFIRE_READ_TOKEN" \
  --data-urlencode "sql=SELECT start_timestamp, span_name, duration,
    attributes->>'gen_ai.usage.output_tokens' out,
    attributes->>'gen_ai.response.finish_reasons' finish
    FROM records WHERE span_name LIKE 'chat%' ORDER BY start_timestamp DESC LIMIT 20"
```

`finish_reasons` is the first field to look at on any agent behaving oddly.

## Known limitations, deliberately left

- **Results importer only reads `h3`-level "Results"** under a mapped `h2`. The
  WI page nests the *Republican* gubernatorial results at `h4` under
  `h3 Governor`, so only the Democratic primary imports. Deeper heading nesting
  is the fix.
- **CA 2024 has both a regular and a special Senate election** on one page; both
  currently key to one contest. Needs a second importer invocation with the
  special's own parameters.
- **One WI poll row fails** to parse (1 of 25). Look at the log before assuming
  it is a bug — a refusal is often correct.
- **FEC includes paper filings.** Gary Peters appears as a 2026 MI Senate
  candidate because he filed, though he is retiring. That is what the source
  asserts; review is the place to prune it.
- **`won` is null for general/runoff results** because those sections have no
  "Nominee" roster. Correct — a general has a winner, not a nominee — but it
  means "who won the general" is not yet answerable from `contest_result`.

## Things that will bite you

The full list is `ingestion-roadmap.md` §10. The five that cost the most time:

1. **`make test-db` used to destroy the dev database.** Fixed — the suite has its
   own database and a guard refuses the app's — but the guard silently did
   nothing at first because `.env` omits the port and the test URL spells it out.
   Any safety check you add, test that it *fires*.
2. **Real reference data finds bugs fixtures cannot.** The OCD import merged 154
   "Washington township" entities into one because an identifier miss fell
   through to name matching. Run importers against the live file before trusting
   entity counts.
3. **Two writers of one predicate produce contradictions.** `contest_result.won`
   defaulted to `False`, so a vote-count claim silently asserted "did not win"
   beside an outcome claim asserting "won". One writer per predicate, and nullable
   fields for "the source did not say".
4. **Agents emit naive datetimes.** A date has no offset to state. Use
   `ScrapedDateTime` from `research/scraped.py`, which attaches UTC; precision is
   carried separately so nothing is invented.
5. **`TemporalDurability` retries model calls forever by default.** A too-short
   `start_to_close_timeout` becomes a paid infinite loop, not a failure.
   `AGENT_MAX_ATTEMPTS` caps it — keep the cap.

## Running things

```bash
docker compose up -d              # postgres, minio, temporal
make migrate                      # or `make stamp` on a create_all database
make test-db                      # 344 tests; needs postgres + minio
make lint

make import-ocd                   # 47k jurisdictions, ~10 min
make import-fec CYCLE=2026
uv run python -m predictelection.importers.run wikipedia-polls \
  --url <race article> --division ocd-division/country:us/state:xx \
  --office us-senate --cycle 2026 [--normalize]
uv run python -m predictelection.importers.run wikipedia-results \
  --url <race article> --division ... --office ... --cycle ...

make worker                       # in one terminal
make research SUBJECT="..." KIND=debates|structure|candidacies
```

`--normalize` lets a model rewrite cells the strict parsers refuse; the rewrite
is re-parsed strictly and the revision is marked `origin=model`. Off by default,
and the six-race corpus needs it for nothing.
